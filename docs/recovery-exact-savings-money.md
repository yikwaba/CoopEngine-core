# REC-06 exact savings posting and balances

Savings deposits, direct withdrawals and approved withdrawal posting now retain integer kobo from validated input/NUMERIC database values through account balance calculations, transaction projections and journal lines. Insufficient-funds checks and stored withdrawal-approval thresholds use exact comparisons. Approval amounts are passed into the existing approval engine as bounded JSON numbers; replacing that engine's financial contract remains separate work. HTTP account/statement/preview response numbers remain compatible and their full-range display precision is still open.

Monthly interest continues to use PostgreSQL numeric rate multiplication and rounding, retaining the resulting decimal strings for sums, per-member journals, balance updates, transactions, posting totals and audit metadata. Preview totals are summed exactly before the legacy numeric response conversion. Interest posting locks eligible accounts in ID order and uses those locked snapshots through commit, preventing a concurrent deposit/withdrawal balance from being overwritten. This preserves the current monthly/current-balance policy; it does not introduce daily accrual, historical restatement, fee rules or new approval requirements.

Public amounts and withdrawal thresholds accept positive/non-negative values respectively, at most two decimal places, with the existing numeric-input ceiling of 100 billion naira. Excess precision is rejected rather than silently rounded. Database balances and approved withdrawal amounts stay decimal strings at the full NUMERIC(19,2) range. Overflow rolls back the full transaction.

Twelve new disposable PostgreSQL journeys cover repeated one-kobo deposits, partial/full withdrawals, overdraft rejection, concurrent deposits/withdrawals, one-kobo movements beyond binary-number precision, maximum supported input, invalid precision/duplicate-key/overflow rollback, closed-period rollback, three interest/rate boundaries, concurrent interest/deposit conservation, interest overflow rollback and exact approval thresholds. Synthetic large opening balances isolate arithmetic; they are not reconciliation of existing history. All production data and providers remain untouched.
