# Journal submission retry identity

Stacked on draft PR #29, whose cumulative local staging installation (including PR #28) was user reported passed on 7 October 2026 at 21:31 Africa/Lagos. Production remains unchanged.

POST /ledger/journals/:id/submit retains its existing empty-body contract and HTTP 200 response. Its natural intent is the organization, journal ID and actor: ledger.submit with entity:<journalId>, fingerprint {actorUserId,journalId}. No new client-generated server retry key is required. Concurrent identical calls serialize and return the original SUBMITTED acknowledgement. A different actor conflicts after the original actor has completed submission. Current authentication, journals.create permission and browser account scope still gate replay.

DRAFT state check/lock, state update, one journal.submitted audit, original journal response read and receipt completion share one transaction. This removes the post-commit response lookup gap. Audit or receipt-finalization faults roll back the state and receipt. A completed receipt replays after posting, reversal or period locking without resetting status, reopening the period, allocating counters or posting money. Unknown/foreign journals return not found; invalid UUIDs reject. An incomplete receipt requires reconciliation. Historical SUBMITTED, POSTED or REVERSED entries without a submission receipt fail closed; no original response or actor is fabricated. Existing submission/approval permissions, posting period checks and approval policy remain separate controls.

The /journals screen lists up to 200 recent journals, submits DRAFT rows, reports original acknowledgement and offers current-record lookup. The draft form links to it. Submission uses the shared natural-intent transport and cross-tab lock; the original route, empty body and account scope persist across uncertain results and browser restart. Recovery displays the original record/status and offers current lookup. Same-origin/profile only. This bounded register is not a completed accounting workflow.

Thirteen PostgreSQL cases cover concurrency, original actor, authentication/current grants/scope, invalid/unknown/foreign records, audit and receipt-finalization fault rollback, distinct journals/tenants, incomplete and historical refusal, and later-state replay. Five browser transport regressions cover target/body durability, competing tabs, changed unresolved details, account changes and malformed acknowledgements. Isolated Chromium uses the actual register, commits then drops a response, refuses a competing tab, closes/reopens the persistent profile, recovers the original SUBMITTED record/body/scope, clears the observer, checks current state and mobile width. Synthetic savings and posted journals remain unchanged.

No migration. The growing full API regression suite retains per-test time limits and now has a bounded 15-minute runner limit (previously 10), within the existing 25-minute integration job limit; this prevents the added coverage from exhausting the previous near-full limit. Final-head CI/staging and user local installation remain separate evidence gates.

Remaining: exact manual-ledger arithmetic, full accounting/approval/loan policy and reporting acceptance, register pagination/configuration, historical reconciliation, cross-device discovery and independent finance/provider/production acceptance. No production merge/deployment.
